# CLA Migration and Historical Contributions

This note explains how e-dialect will introduce the Contributor License
Agreement (CLA) without rewriting the rights attached to earlier work.

## Existing open-source grants

Every public release remains governed by the license under which it was
published. A later CLA, repository policy, or alternative commercial license
does not revoke rights that recipients already received under an open-source
license.

The CLA is not retroactive by default. A contributor may explicitly accept an
agreement that covers their past, present, and future Contributions, but an
unsigned historical contributor is not deemed to have accepted it. A commit,
pull request, checkbox, or lack of objection is not a substitute for an
auditable signature record.

After the CLA check is activated for a covered repository, each new pull
request must pass the configured explicit-acceptance process before merge.

## Alternative commercial relicensing

Beijing Taju Technology Co., Ltd. may provide an alternative commercial or
proprietary license only for material where it can demonstrate one of the
following:

- Beijing Taju owns the relevant copyright;
- a valid ICLA or CCLA grants the necessary sublicensing and relicensing rights;
  or
- another written instrument grants the necessary rights.

This authority must be assessed by contribution and path. It must not be
presented as whole-repository authority merely because a repository uses an
open-source license or later adopts a CLA.

Historical code with an incomplete rights chain remains available under its
existing open-source terms. If it cannot be relicensed, it must remain under
those terms or be excluded from or independently replaced in an alternative
proprietary build. Third-party code and separately governed data, media,
models, and brand assets remain subject to their own terms.

## Audit handling

Maintainers may keep a private contributor and rights-chain audit for this
purpose. Legal names, email addresses, signature records, or other personal
data must not be copied into public GitHub issues or public audit reports. See
[`CLA_PRIVACY.md`](./CLA_PRIVACY.md).

# CLA 迁移与历史贡献说明

e-dialect 引入 CLA 不会改写历史版本已经授予公众的开源权利。每个公开版本继续适用其
发布时的许可证，后续 CLA、组织政策或替代商业许可均不撤销这些既有授权。

CLA 不会让未签署的历史贡献者“自动签署”。贡献者可以显式接受覆盖其过去、现在和
未来贡献的协议，但 Commit、Pull Request、复选框或未提出异议均不能代替可审计的
签署记录。CLA 检查在适用仓库启用后，新 PR 必须在合并前通过显式接受流程。

北京塔聚科技有限责任公司只可在以下可证明的范围内提供替代商业或专有许可：其自身
拥有版权的材料；有效 ICLA/CCLA 已授予必要再许可和重许可权的贡献；或其他书面文件
已经授予相应权利的材料。该判断必须落实到具体贡献和路径，不能仅因仓库采用开源
许可证或后来启用 CLA，就声称取得整仓商业重许可权。

权利链尚不完整的历史代码继续按既有开源条款提供；无法重许可的部分应继续保留原
条款，或在替代专有版本中排除或独立替换。第三方代码以及单独治理的数据、媒体、
模型和品牌资产继续适用各自条款。

维护者可以为上述目的保留私密的贡献者与权利链审计，但不得把法定姓名、邮箱、签署
记录或其他个人数据复制到公开 GitHub Issue 或公开审计报告。详见
[`CLA_PRIVACY.md`](./CLA_PRIVACY.md)。
